# Compatibility fixture

Compile `src/main/java` against the server API, ByteCompanions API, and Adventure. Package the resulting fixture classes with `src/main/resources/plugin.yml` only. Do not bundle ByteCompanions or Adventure classes. The dependency declaration makes the installed plugin provide its public API. Startup logs `BCQA COMPONENT_IDENTITY PASS` only when the public companion name method and fixture resolve the same Adventure `Component` class and the API belongs to another class loader.

Run `qa/spigot-compatibility.mjs` through the Multiplexor Mineflayer harness against an isolated Spigot 26.1.2 instance with this fixture installed and root hot reload disabled. The bot must be an operator. The scenario restores edited plugin files in its cleanup. It places and mines one ore block and creates temporary entities in the disposable world.

The scenario verifies client packets for base companion main-hand, off-hand, and attack interactions before and after reload; it also checks real cow damage, real ore mining, particle packets, and rejection of unsupported general XP configuration. Default bee has no overlays; overlay interactions are not claimed. A separate run or reconnect is needed for fresh-session coverage.

`/bcqa xp block|furnace|fishing|mob` fires synthetic Bukkit events with a fixed base of 10. The fishing check first requires a real fishing-rod cast; the fixture captures that hook and uses it in a synthetic catch event. Results prove source listener transformations only. They do not prove a real fish catch, smelting, mob death, or XP orb collection. The separate real ore assertion proves an actual client mining action reaches the source XP handler and changes the drop amount, without asserting the collected orb total. Protocol checks do not certify client rendering, sound, or resource packs.

`/bcqa` is operator-only. `status`, `state`, and `reset` expose fixture state; `target` and `health` support the real combat check. The fixture removes used fishing hooks after the synthetic catch and removes remaining hooks and combat targets on disable.

`/bcqa vault` reads the installed Vault implementation, selected economy provider, service identity, and the caller's balance. It does not register a provider or change money. The observer loads the optional Vault API only when Vault is present, so the regular fixture can still run the missing-dependency checks.

`/bcqa guitrace start|state|stop` opts the operator into passive inventory diagnostics. It retains at most 256 open, close, and click observations at LOWEST and MONITOR priority, including cancellation state, inventory identities, and up to 16 stack frames for close events. It does not cancel events or change menus. Each command saves `plugins/ByteCompanionsQA/gui-trace-<uuid>.json` and returns its filename; file output avoids chat truncation. Stop removes the in-memory history, and quitting saves any active trace before removing it. The isolated test driver preserves these files before deleting the instance.

`qa/vault-foundation.mjs` uses Foundation's real administrator command to seed a disposable player's balance, then checks combined money/item purchases, insufficient funds, duplicate and stale payment packets, permissions, and reloads. `qa/vault-foundation-restart.mjs` requires a driver-recorded full process restart before checking the saved balance, paid benefits, inventory, and potion effect. Install the unchanged Foundation artifact and an officially acquired Vault implementation; these scenarios must never use `ByteCompanionsQAEconomy.jar`. Bind each report to the exact external plugin versions and hashes. Folia uses VaultUnlocked and normal restart/reload lifecycle only.

`/bcqa disable` schedules a live ByteCompanions disable on the Bukkit server thread used by the tested Paper and Spigot runtimes. Run `qa/disable-lifecycle.mjs` last: two managed clients remain online while it checks visual removal, stopped particle traffic, attribute cleanup, external potion restoration, and command removal. The scenario restores configuration files without re-enabling the plugin. Restart the server before further checks. This fixture does not certify regionized server shutdown.
